# 科创超跌价值回归策略：需求澄清与设计方案

## 1. 系统目标

该策略系统用于科创板 688 股票的多标的组合回测，核心目标是把“超跌价值筛选、日线信号择时、固定仓位执行和风险优先退出”整合到同一流程中。

系统由四层组成：
1. 选股层：基于科创约束、上市时长、超跌程度、基本面与底部量价特征生成月度股票池。
2. 信号层：在股票池内按日识别 BOLL 与 MACD 买入信号（任一触发即可）。
3. 组合层：执行固定仓位、持仓上限、信号先后顺序买入规则。
4. 风控层：执行 7% 止损、10% 后 30% 回撤止盈、ST 按交易日快照即时卖出。

## 4. 需求澄清（已确认）

### 4.1 股票范围

1. 仅选择科创板 688 开头股票。
2. 行业维度暂不做自动硬过滤，默认覆盖全部科创板。

### 4.2 上市时长窗口

1. 以当月选股日作为计算时点。
2. 保留上市时长在 0.5 年到 2 年之间的股票。
3. 约束口径：182 天 <= 上市天数 <= 730 天。

### 4.3 超跌条件

1. 以复权价格序列计算上市后历史高点。
2. 当前价格较历史高点回撤不低于 50%。
3. 公式：

$$
\text{drawdown} = \frac{\text{current\_price} - \text{post\_list\_high}}{\text{post\_list\_high}}
$$

筛选条件：

$$
\text{drawdown} \le -0.50
$$

### 4.4 基本面硬过滤条件

1. 不亏损：最近完整年报净利润非负。
2. 上市后营收增长：最新完整年报营收 > 上市首个完整年报营收。
3. 上市后毛利率增长：最新完整年报毛利率 > 上市首个完整年报毛利率。
4. 股东质押比例 < 50%。
5. 商誉/净资产 < 30%。
6. 资产负债率 < 70%。

### 4.5 技术面硬过滤条件

1. 底部振幅收窄：近 20 日价格波动小于 20%。
2. 缩量：近 20 日平均成交量 < 近 60 日平均成交量的 80%。
3. 流动性：近 60 日日均换手率 > 1%。

### 4.6 行业景气（主观项）

1. 不纳入自动代码过滤。
2. 人工判断原则：优先板块震荡或上升，规避明显下行周期。

### 4.7 提示性指标（仅输出，不参与筛选）

1. PEG。
2. 研发费用/营收占比。

### 4.8 买入信号（已确认口径）

1. 对入池股票进行 BOLL 与 MACD 信号识别。
2. BOLL 或 MACD 任一出现买入信号即可下单。

### 4.9 卖出规则（已确认口径）

1. 仅由风险控制规则触发真实卖出。
2. BOLL/MACD 的卖出信号只做提示日志，不执行卖出。
3. 股票被移出最新股票池时不卖出，继续持有并执行风险控制。

### 4.10 风控规则

1. 硬止损：单票亏损达到 7% 立即卖出。
2. 动态止盈：盈利超过 10% 后，若盈利回撤超过 30%，执行止盈卖出。
3. ST 风险：按交易日快照判断，若当日处于 ST 区间，立即卖出。

### 4.11 仓位与资金约束

1. 初始资金：100 万。
2. 最大持仓数：5。
3. 单票目标仓位：20%。
4. 不做加仓减仓：买入即目标 20%，卖出即全平。

### 4.12 运行方式

1. 每月执行一次选股，生成当月股票池。
2. 日线频率进行信号识别与交易决策。
3. 买入按信号出现先后顺序执行。
4. 超过 5 个仓位后，后续买入信号忽略并记录日志。
5. 已持仓股票即使不在新池中，仍继续信号识别与风控管理。

## 5. 设计方案

### 5.1 架构原则

1. 选股器不新建模块，在现有选股器中新增科创专用功能入口。
2. 交易策略保持独立文件，实现独立运行与独立迭代。
3. 数据层优先复用已有原始缓存，新增派生特征使用独立缓存键，避免互相覆盖。

### 5.2 选股层设计

#### 5.2.1 实现位置

在现有选股器中新增专用入口方法，例如：

- select_star_value_reversion(trade_date: str, verbose: bool = True)

#### 5.2.2 过滤流水（建议顺序）

1. 股票范围过滤：仅 688。
2. 上市时长过滤：182 到 730 天。
3. ST/退市过滤。
4. 超跌过滤：回撤 >= 50%。
5. 年报亏损过滤。
6. 营收增长过滤（最新完整年报 vs 上市首个完整年报）。
7. 毛利率增长过滤（同口径）。
8. 质押比例过滤。
9. 商誉占比过滤。
10. 资产负债率过滤。
11. 振幅收窄过滤（20 日）。
12. 缩量过滤（20/60 日均量）。
13. 流动性过滤（60 日均换手率）。

#### 5.2.3 输出字段

1. 基础信息：symbol, name, industry, trade_date。
2. 核心筛选指标：listing_days, drawdown_from_post_list_high, revenue_growth_since_list, gross_margin_growth_since_list, pledge_ratio, goodwill_ratio, debt_ratio, amp_20d, vol_ratio_20_60, avg_turnover_60d。
3. 提示字段：peg, rd_to_revenue_ratio。
4. 审计字段：各过滤步骤通过标记或淘汰原因（用于复盘）。

### 5.3 信号与交易层设计（独立策略文件）

#### 5.3.1 策略文件

新建独立策略文件，建议命名：

- akq_stock_strategy_star_value_reversion.py

#### 5.3.2 信号逻辑

1. BOLL 买入信号：沿用下轨反弹类逻辑。
2. MACD 买入信号：采用日线金叉判定。
3. 买入触发：BOLL 或 MACD 任一触发即可。

#### 5.3.3 卖出执行边界

1. 硬止损触发即卖出。
2. 动态止盈触发即卖出。
3. ST 状态触发即卖出（按交易日 ST 快照区间判定）。
4. BOLL/MACD 卖出只提示，不触发真实卖单。
5. 出池不卖出。

### 5.4 资金管理与订单约束

1. 最大持仓 5 只。
2. 单票固定 20% 目标仓位。
3. 买入顺序按信号触发时序，满仓后忽略后续新开仓信号。
4. 仅允许两类仓位变化：0% -> 20%，20% -> 0%。

### 5.5 调度与生命周期

1. 月度选股：每月首个交易日生成股票池快照。
2. 日线识别：每个交易日收盘后执行信号与风控。
3. 股票池作用：仅限制新开仓。
4. 持仓管理：持仓标的持续参与日线识别与风控，直到风控退出。

### 5.6 数据与缓存策略

1. 原始行情/财务数据优先复用本地已有缓存。
2. 新策略新增字段采用独立缓存键前缀（例如 star_vr_*）。
3. 保证新增功能不破坏现有选股流程缓存。

### 5.7 可观测性与日志

建议输出以下日志与报表统计：

1. 月度入池数量、入池名单。
2. 买入触发次数（BOLL/MACD 分开计数）。
3. 满仓被忽略信号次数。
4. 卖出触发次数（止损/止盈/ST 分项统计）。
5. 信号卖出提示次数（不执行交易）。

### 5.8 验证方案

#### 5.8.1 规则验证

1. 选股规则单项验证：上市窗口、回撤、财务阈值、量价阈值。
2. 交易规则验证：5 仓上限、20% 固定仓位、三类风险卖出。
3. 行为边界验证：信号卖出不交易、出池不卖出。

#### 5.8.2 回归验证

1. 确认新增专用入口不影响现有通用选股入口输出。
2. 确认现有策略脚本运行行为不受新增功能影响。

## 6. 实施边界与非目标

1. 行业景气判断保持人工决策，不进入当前自动化实现。
2. 暂不引入加仓减仓、再平衡或行业配比优化。
3. 暂不将提示性指标（PEG、研发占比）纳入硬过滤。

## 8. 当前确认结论（最终）

1. 选股器方案：在现有选股器内新增科创专用功能，不新建选股模块。
2. 策略方案：策略文件独立实现，尽量减少对其他策略类的依赖。
3. 数据方案：优先复用原始缓存，新增派生缓存独立命名。
4. 买入口径：BOLL 或 MACD 任一买入信号即可下单。
5. 卖出口径：仅风险卖出；信号卖出仅提示；出池不卖出。

## 10. 实施过程中的澄清触发条件

出现以下情况时，需要与策略负责人立即确认，不应自行假设：

1. 数据字段缺失：若资产负债率或研发费用字段在目标日期不可用，需确认是回退最近一期还是剔除标的。
2. ST 判定口径：已定为按交易日快照；若缺少 start_date/end_date 字段，回退 ann_date 作为起始日。
3. 上市首个完整年报缺失：若无法定位首个完整年报，需确认是否跳过该股或放宽为首个可用年报。
4. 换手率缺失：若部分股票历史换手率连续缺失，需确认是否允许成交量替代。
5. 极端市场日：若当日可交易标的大量跌停导致执行偏差，需确认是否增加成交约束模拟。

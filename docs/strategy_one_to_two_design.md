# 一进二打板策略：功能与设计说明

## 1. 策略定位

一进二策略用于识别“昨日首次涨停、今日可能继续连板”的短线交易机会。策略只使用日线 OHLCV 数据，不依赖分时数据或基本面数据，核心流程为：

1. 确认上一交易日收盘涨停。
2. 排除上一交易日的一字涨停板。
3. 在当前交易日开盘时检查高开幅度、开盘涨停状态和成交量条件。
4. 满足条件后按当前开盘价买入。
5. 持仓期间，涨停则继续持有；未连板则退出；触及止损则退出。

该策略属于短周期、事件驱动型策略，目标是捕捉首板后的第二个涨停板，不构成投资建议。回测结果受涨停成交、滑点、复权方式、停牌和数据完整性影响较大。

## 3. 交易流程

### 3.1 买入流程

对当前没有持仓的标的，策略按以下顺序判断：

1. **持仓数量检查**：当 `buy_prices` 中的标的数量达到 `max_positions` 时，不再开新仓。
2. **历史数据检查**：至少需要 3 根收盘价，无法取得足够历史数据时跳过。
3. **昨日涨停检查**：
   - 将昨日收盘价与前日收盘价进行比较。
   - 根据股票代码前缀推断涨停比例。
   - 昨日收盘价达到计算出的涨停价附近时，视为涨停。
4. **一字板过滤**：若昨日开盘价达到涨停价，且昨日最低价等于最高价，则跳过该标的。
5. **今日高开检查**：
   - 计算公式：

     $$
     \text{open\_pct} = \frac{\text{today\_open} - \text{yesterday\_close}}{\text{yesterday\_close}}
     $$

   - 默认要求高开幅度在 3% 到 7% 之间，包含区间端点。
6. **今日开盘可成交检查**：今日开盘价不能达到基于昨日收盘价计算出的涨停价。
7. **成交量检查**：当可取得至少两根成交量数据时，要求今日成交量不低于昨日成交量的 80%。
8. **下单**：以当前日线的开盘价调用 `order_target_percent(position_pct, symbol, price=buy_price)`，目标仓位默认为总资产的 20%。

### 3.1.1 同日候选排序与递补

全市场回测会在下单前预计算每个交易日的候选队列，不再按股票代码先到先得。候选按以下稳定顺序排序：

1. 昨日成交额降序，优先流动性更高的标的。
2. 今日高开幅度距离 5% 的绝对值升序。
3. 今日成交量/昨日成交量降序。
4. 股票代码升序，作为最终稳定排序键。

买入订单使用 IOC。高优先级候选未成交并被取消时，策略通过订单回调立即递补下一只候选；实际成交或待成交名额达到最大持仓数后停止递补。候选排序在回测前完成，卖出和风控规则不受影响。

### 3.2 持仓流程

当前持仓优先执行卖出判断，不再执行买入判断：

1. 先检查当日最低价是否触发止损。
2. 未触发止损时，检查当日收盘是否继续涨停。
3. 当日继续涨停则保持持仓。
4. 当日未涨停则平仓，原因记录为“未连板(尾盘卖出)”。

策略启用 `t_plus_one=True` 的示例回测配置，意图是遵守 A 股 T+1 约束，避免买入当日卖出。实际成交时点仍由回测引擎的订单撮合规则决定。

## 4. 涨停价判定

方法 `_get_limit_price` 按股票代码前缀计算涨停价：

| 股票代码前缀 | 使用比例 | 计算方式 |
| --- | ---: | --- |
| `688`、`689`、`300`、`301` | 20% | `round(prev_close * 1.2, 2)` |
| `8` | 30% | `round(prev_close * 1.3, 2)` |
| 其他代码 | 10% | `round(prev_close * 1.1, 2)` |

方法 `_is_limit_up` 使用“收盘价大于等于计算涨停价减 0.01”作为判定条件，以处理两位小数价格的误差。

### 4.1 判定边界

当前实现是基于代码前缀的简化规则，未读取交易所、特殊处理股票、上市首日或临时涨跌幅限制等状态。因此以下情况需要在使用前单独确认：

1. ST、*ST 股票的涨跌幅限制可能与普通股票不同。
2. 新股、复牌股或其他特殊交易状态可能不适用固定比例。
3. 价格复权方式必须与涨停判定的前收口径一致。
4. 代码中使用 `round` 计算价格，无法覆盖所有交易所价格精度和边界规则。

## 5. 卖出与风控设计

### 5.1 固定止损

默认参数 `stop_loss_pct=-0.05`。当日最低价满足以下条件时立即触发卖出：

$$
\text{bar.low} \leq \text{buy.price} \times (1 + \text{stop\_loss\_pct})
$$

默认即买入价下跌 5% 时止损。卖出日志会记录当前收盘价、止损原因以及按收盘价计算的盈亏比例。

### 5.2 连板持有

若当日收盘价被判定为涨停，策略返回“不卖出”，将持仓保留到下一交易日继续判断。这里的“继续持有”只依据当日收盘是否涨停，不包含炸板次数、封单金额、封板时间等分时级别信息。

### 5.3 未连板退出

只要未触发止损且当日未涨停，策略就执行 `close_position(symbol)`，日志原因是“未连板(尾盘卖出)”。代码注释将该行为描述为尾盘卖出，但当前策略输入为日线，无法在策略内部验证真实尾盘成交价格。

## 6. 参数说明

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| `high_open_range` | `(0.03, 0.07)` | 今日相对昨日收盘的高开幅度上下限，包含边界 |
| `volume_ratio_min` | `0.8` | 今日成交量相对昨日成交量的最低比例 |
| `stop_loss_pct` | `-0.05` | 止损比例，负数表示亏损阈值 |
| `position_pct` | `0.2` | 单只股票目标仓位，占总资产比例 |
| `max_positions` | `5` | 最大持仓标的数量 |

策略没有实现加仓、减仓、分批止盈或动态调整仓位。一次买入目标仓位为 `position_pct`，卖出时通过 `close_position` 全部平仓。

---

## 7. 资金管理与组合约束

1. 默认每只股票占总资产 20%。
2. 默认最多同时持有 5 只股票，理论目标总仓位上限为 100%。
3. 持仓数量依据 `buy_prices` 字典统计，而不是单独查询整个账户的所有持仓。
4. 买入后以代码为键保存买入价；平仓成功后移除该记录。
5. 当多个标的在同一交易日满足条件时，实际处理顺序取决于回测框架提供 `on_bar` 的标的遍历顺序。
6. 佣金和滑点不在策略类中计算，由 `run_backtest` 的参数统一配置。

需要注意，固定 20% 目标仓位与手续费、滑点、现金余额之间的最终成交结果由回测引擎决定；目标仓位并不等同于保证每次都能完整成交。

## 8. 数据要求

策略每个标的至少需要以下日线字段：

1. `open`
2. `high`
3. `low`
4. `close`
5. `volume`
6. `symbol`
7. `datetime`

历史数据通过框架的 `get_history` 获取：

1. 买入判断需要 3 根 `close`、`open`、`high`、`low` 数据。
2. 买入判断需要至少 2 根 `volume` 数据。
3. 卖出判断需要至少 2 根 `close` 数据。
4. 数据不足时，买入条件直接判定为不满足；成交量历史不足时，当前实现不会额外拒绝买入。

数据源示例使用 `TushareStockDataManager` 获取并缓存 Tushare 日线数据，策略本身不负责下载数据。

## 9. 运行方式

### 9.1 环境准备

设置 Tushare token：

```powershell
$env:TUSHARE_TOKEN = "your_token"
```

然后运行：

```powershell
python akq_stock_strategy_one_to_two.py
```

### 9.2 示例回测配置

当前脚本入口默认使用：

1. 初始资金：`1000000.0`
2. 佣金率：`0.0005`
3. 滑点：`0.0002`
4. T+1：`True`
5. 数据区间：`20240101` 至 `20241031`
6. 数据缓存目录：`tsdata_unadj`（未复权行情，与其他策略的复权行情缓存隔离）
7. 每日候选按成交额、高开幅度和量比排序，IOC 未成交后按队列递补。

脚本先从 Tushare 获取示例股票池数据，过滤空数据后取 `stock_data_dict` 中的第一只股票进行回测。虽然策略类本身可被组合回测调用，但当前 `__main__` 示例并未对股票池逐只运行或构建多标的组合。

### 9.3 输出

1. 终端打印 `result.metrics_df`。
2. 回测报告保存到 `reports/one_to_two_<symbol>_<timestamp>.html`。
3. `include_trade_kline=True`，报告包含交易 K 线信息。
4. 日志输出买入、卖出价格、日期、卖出原因和按收盘价估算的盈亏比例。

## 10. 验证方案

建议使用构造数据或最小回测样本覆盖以下场景：

1. 历史数据不足 3 根时不买入。
2. 昨日未涨停时不买入。
3. 昨日一字板时不买入。
4. 今日高开低于 3% 或高于 7% 时不买入。
5. 今日开盘涨停时不买入。
6. 今日成交量低于昨日成交量的 80% 时不买入。
7. 已达到 5 个持仓时忽略新信号。
8. 当日最低价触发 5% 止损时卖出。
9. 当日继续涨停时保持持仓。
10. 当日未涨停且未止损时平仓。
11. T+1 配置下，买入当日不会被卖出逻辑重复处理。
12. 代码前缀为主板、双创和北交所时，涨停价比例分别正确应用。

重点检查订单价格和撮合时点：策略以日线开盘价作为买入参考价，以日线数据触发退出，但“尾盘卖出”并不是由当前代码精确模拟的成交时点。

## 11. 当前实现边界与后续改进

### 11.1 当前边界

1. 不使用分时数据，无法判断封板时间、炸板、封单强度和真实尾盘成交。
2. 不过滤 ST、退市风险、停牌、流动性和可交易性状态。
3. 涨停比例仅通过股票代码前缀推断。
4. 买入价格记录保存在策略实例内存中，策略重启或状态恢复时不会自动从账户成交记录重建。
5. 代码中存在同名嵌套 `OneToTwoStrategy` 类定义；当前交易方法属于外层类，但该结构容易造成阅读和维护歧义，后续应清理。
6. 文件头部导入了 `List`，当前实现未使用。

### 11.2 改进方向

1. 使用交易所和交易日历数据替代代码前缀推断涨停幅度。
2. 增加 ST、停牌、退市整理和新股状态过滤。
3. 在支持的情况下接入分时数据，显式模拟开盘买入与尾盘卖出。
4. 用实际成交回报或持仓成本重建 `buy_prices`，提高恢复运行能力。
5. 将单标的示例扩展为真正的多标的组合回测，并明确同日信号排序规则。
6. 增加自动化规则测试和交易日志统计，区分止损、未连板和满仓忽略等原因。

---

## 12. 设计结论

该策略以简单、明确的日线规则实现“首板后次日接力”：昨日涨停且非一字板是前置条件，今日高开 3% 到 7%、未开盘涨停且成交量达到阈值时买入；持仓后优先止损，涨停继续持有，未连板退出。资金管理采用单票 20%、最多 5 票的固定目标仓位。

策略适合作为日线级规则验证和回测原型。若用于更接近实盘的打板研究，首先应补充分时成交、涨停状态、特殊交易状态和订单可成交性建模。
